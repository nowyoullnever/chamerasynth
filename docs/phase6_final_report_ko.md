# Phase 6 최종 보고서

## 결과

1. `0x5025` 생산자는 식별하지 못했다. 보존된 내보내기에서는 소비자 `0x63b0`과 `0x1c9c4`가 각각 `0x108`을 발행하는 것만 검증된다.
2. 안전한 카메라 전용 교체 지점은 찾지 못했다. `0x6134`는 시작 UI·오디오·이벤트가 혼합되어 있고, `0x2d31c`의 간접 콜백 ABI는 미확정이다.
3. 제안한 호스트 설계에서는 전달된 `0x5025`의 업데이터 도달성을 보존한다. 실제 펌웨어의 업데이트 복구·실행은 증명하지 않는다.
4. 오디오 경로는 `0x12f0c → 0x133f0 → *(state+8)`까지 좁혔다. PCM/DAC/PWM/DMA와 연속 출력 인터페이스는 확인하지 못했다.
5. 실제 구현은 하드웨어 주소 없는 신스 애플리케이션 골격, 모의 오디오 HAL, 강화된 이벤트 통합 모델과 테스트다.
6. 안전한 훅과 삽입 영역이 없으므로 새 ARM 펌웨어 통합 모듈이나 수정 이미지는 만들지 않는다. 기존 분리형 ARM ABI 프로토타입만 유지한다.
7. 원본 펌웨어가 없는 현재 복제본에서는 바이너리 의존 기존 테스트가 명시적으로 skip되고, 나머지 분석·호스트 테스트가 실행된다. 원본을 제공하면 해당 테스트는 다시 원래의 identity/protected-range 검증을 수행한다.
8. 모든 Phase 6 소스·문서·결과 ZIP은 `main`에 커밋·푸시 대상이다. 최종 푸시 SHA는 작업 종료 시 확인한다.

## 실기기 POC 우선순위

첫 유용한 후보는 Test A(기존 BEEP 등 짧은 리소스의 control-flow 비변경 교체)다. 그러나 실제 리소스 범위·길이·정렬·메타데이터·검사값을 복원하지 못했으므로 승인되지 않았다. `tools/resource_replacement_prototype.py`는 증명된 매니페스트가 주어질 때에만 별도 복사본에서 허용 범위 외 바이트 불변을 확인하는 오프라인 도구다.

Test B(버튼-재생)는 물리 버튼과 `0x700x`/selector 연결이 미확정이고, Test C(생성 PCM)는 `0x133f0` 이후 드라이버 ABI가 미확정이다. 따라서 Test A → Test B → Test C 순서가 맞지만, 현재 Phase 6에서는 어느 것도 설치하지 않는다. stock restore 파일은 부팅 실패 시 SD updater 접근 또는 복구를 보장하지 않으며 외부 복구 경로가 확인되지 않았다.

## 첫 하드웨어 신스 시험 전 정확한 차단점

권한 있는 원본 이미지를 다시 제공해 `0x5025` 생산자의 메시지 코드·큐 인자·간접 호출을 추적해야 한다. 같은 import에서 `0x133f0`과 state `+8` 콜백의 실제 본문을 분석해 PCM 백엔드 ABI를 회수해야 한다. 마지막으로 실행 매핑·안전한 코드 영역·업데이터 길이/지우기 규칙을 독립적으로 증명해야 한다. 이 세 조건 전에는 패치·SD 패키지·장치 시험을 하지 않는다.
